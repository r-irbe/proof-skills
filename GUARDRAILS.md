### Proof writing — [`lean-proof`](skills/lean-proof/SKILL.md)
- GT-06: FAIL: Writes 3–5 tactics before reading diagnostics -> REMEDY: One tactic at a time, gated on `done`/diagnostics
- GT-07: FAIL: Chases a linter warning while an unsolved-goals error is open -> REMEDY: Error-priority order (G-3, G-4): errors before warnings
- GT-08: FAIL: Fills helper-lemma `sorry`s before touching the target theorem -> REMEDY: Target theorem first; helpers only as reached
- GT-09: FAIL: Declares success while a `sorry` remains -> REMEDY: Verify pass: no `sorry`, no error, diagnostics re-read
- GT-10: FAIL: Fights `motive is not type correct` with more `rw` instead of generalising -> REMEDY: Generalise-then-instantiate (G-9)
- GT-11: FAIL: Retries `rw` with "pattern not found" on goals whose summand contains a non-reducible type synonym or a semireducible definition — the matcher runs below default transparency and cannot unfold these -> REMEDY: `simp only` with the exact lemma list, then `exact` the residual identity; supply bare commutation lemmas as terms (they loop as simp lemmas); probe goal shapes with live LSP `plainGoal` queries, never file-polluting `trace_state` or `sorry` placeholders
### Proof review — [`lean-proof-review`](skills/lean-proof-review/SKILL.md)
- GT-12: FAIL: Rewrites the proof inline instead of suggesting changes -> REMEDY: Review produces findings, not silent rewrites
- GT-13: FAIL: Approves at L4 without confirming L1/L2 passed -> REMEDY: Checklist order is mandatory: L1 → L2 → L3 → L4
- GT-14: FAIL: Misses vacuous-truth L3 failures behind a clean `aesop` close -> REMEDY: Inspect what `aesop` actually closed, not just that it closed
- GT-15: FAIL: Cites a pitfall without quoting line numbers or the source rule -> REMEDY: Every finding carries location + rule reference
- GT-16: FAIL: Accepts an "independent routes" claim without checking it — when a project claims two or more independent proofs of one theorem, the routes may share machinery (imports, helper lemmas, substrate definitions) -> REMEDY: Before repeating an independence claim in a verdict, verify the routes share no machinery; a shared-lemma discovery downgrades the claim to "partly independent" in the review record
### Enforcement & gates — [`lean-enforcement`](skills/lean-enforcement/SKILL.md)

- GT-19: FAIL: Runs `enforce_all.sh` when a single script would have answered the question -> REMEDY: Run the narrowest gate that answers the question
- GT-20: FAIL: Skips the structured-result emit step -> REMEDY: Emit the structured result; skipping = incomplete
- GT-21: FAIL: Trusts a green gate whose generated probe/scan manifest is stale — newly registered modules or targets are silently unscanned, and a summary can be clean while whole namespaces went unscanned -> REMEDY: After registering new targets, regenerate generated probe scripts and rerun before quoting the result; treat per-item coverage gaps inside the gate's own report as findings, not noise; close unexplained gaps with a targeted spot-check (e.g. a single-declaration `#print axioms` probe) before declaring the gate clean

- GT-48: FAIL: Declares success on a green `lean --version` without checking `lake env lean --version` -> REMEDY: Both version probes must agree before handoff
- GT-49: FAIL: Hands off to `@lean-proof` while the two `--version` commands disagree -> REMEDY: Resolve the toolchain mismatch before handoff
- GT-50: FAIL: Treats destructive-command approvals as reusable prose, or HITL rulings as free text -> REMEDY: Destructive commands require single-use sha256+TTL approval ledger records; HITL gates are JSON-schema-typed packets (approve/reject/defer) — see the filab investigation plan (PLAN-FILAB-DEEP-INV) for the full design

- GT-53: FAIL: Conflates capability tiers into one enum, or gates irreversible actions with re-runnable checks -> REMEDY: Capability tiers are distinct newtypes per surface over a base ladder; irreversible actions fail closed with signed risk-acceptance; environment scrubbing re-opens threat surfaces — prefer per-subject opt-in with dual-digest audit rows (filab third-look, N8; extends GT-50)
- GT-54: FAIL: Reads a passing check as closure, or treats a frozen measured NO-GO as liftable by offline work -> REMEDY: Passing checks are telemetry, never closure; a frozen measured NO-GO is TERMINAL and lifts only through named human acts (SEAL + powered IRB study + sealed rerun) — q AGENTS.md MASTER BLOCKER pattern (q investigation, C1)
- GT-55: FAIL: Grants a governance tool authority by default, or lets it judge its own output -> REMEDY: Governance-tool lifecycle: staged authority promotion (warn-first → blocking ratchet after 3 clean rounds, human `--strict` opt-in); honesty-wall "WHAT THIS IS NOT" headers; approval-language denylist with negation exceptions; falsifier non-vacuity proofs (rejects adversarial auto-approve AND accepts well-formed input); worker contracts stdlib-only, no I/O/randomness/network (q investigation, C2)
- GT-56: FAIL: Lets one artifact affirm what another denies, or leaves human escalation unnamed -> REMEDY: Layered denial: no single artifact may affirm what another denies; human acts are named and scarce (SEAL, HITL ratification, paste-into-ledger); analysis/execution separated by repo layout; provenance to the byte (filenames carry UTC/host/SHA/dirty) (q investigation, C9)
- GT-57: FAIL: Installs a hard barrier without naming its mandate, or lets eager sealing/clamping stop all progress -> REMEDY: Barrier proportionality: hard stops (terminal NO-GO, frozen clamp, no-bypass block) are reserved for the subset mandated by regulation, procedure, or law — every hard barrier must cite its mandate in a barrier registry, and an unjustified hard barrier is itself a defect. Everywhere else the design is fail-open with compensating controls: provisional continuation in a quarantined scope (no protected-path writes, reversible, enhanced audit trail), reduced blast radius, additional review. Blocked ≠ stopped (operator directive 2026-09-15; scopes GT-54/55/56)
- GT-58: FAIL: Leaves human-approved work stalled behind a gate, or uses promotion timeouts by default -> REMEDY: Continuity under approval: once a human approves via the HITL gate, a stalled pipeline is a defect — approved-but-blocked items carry escalation SLAs with named owners and auto-escalate on expiry. Promotion timeouts are the exception, not the mechanism: use them sparingly, only where a rule class explicitly defines them (e.g. GT-55's ratchet), never as a generic barrier. Where continuation is safe, proceed provisionally with the compensating controls of GT-57 and reconcile at the gate (operator directive 2026-09-15)
- GT-59: FAIL: Lets capability expansion ride on prose rules, scalar trust scores, or untraceable overrides -> REMEDY: Capability-governance baseline: append-only ADR ledger at a fixed root with irreversible gate progressions; `CAPABILITY_EXPANSION = always_hitl` behind a static reversible-op whitelist; bash-only-first action surface — a specialized tool must justify a ≥5% task-success uplift; a ~100-line minimal-agent reference keeps the floor honest; operator overrides mint verifiable receipts (Blake3) that become audit rows; trust stays a composite vector with per-dimension vetoes, never a scalar (filab fourth look, N-1/N-2)
- GT-60: FAIL: Lets a gate pass by exiting 0 on its error path, or syncs gate outcomes nowhere -> REMEDY: Enforcement parity: a gate is a gate only when its failure path denies — gate errors and config failures must DENY (fail-closed BLOCK exit code), violation events must land in an event log with a gate→HITL sync queue, and the stub confession ("not yet fully implemented") is a defect class of its own; parity CI replays gate invocations against fixtures so an exit-0 stub cannot masquerade as enforcement (filab seventh look, X-6; the legacy G5 vs nomikon gate_hook.rs arc)
- GT-61: FAIL: Treats a status string as a validation event, or audits one trust regime and assumes the other -> REMEDY: Two-regime validation: EXECUTED validation lives only in gate/council ledgers (verbatim decision_source with timestamp + named approver, last_validated dates, canonical-flip flags, staged pending_actions, implementation_state); status strings (validation_status: pending/validated) are PLEDGES with zero executions unless bound to a ledger row — audit both regimes independently, never infer one from the other (q fifth look, Y-3: 0/24 learning notes executed vs gate ledgers running)
- GT-62: FAIL: Lets a pipeline stage run out-of-order, or authors from unaccepted inputs -> REMEDY: Pipeline-as-permissions: each stage's tool REFUSES to run before its gate — an ADR moves proposed -> accepted only behind a recorded human decision_signoff; specs are authored only from ACCEPTED ADRs; tasks enforce the AC <-> design-component <-> TASK isomorphism with [Fit:] thresholds; eval dispatch fails closed on unbound cases (algos authoring pipeline, K-2/K-3)
- GT-63: FAIL: Trusts a single-threshold gate to carry both publication and acceptance, or treats a council score as authority -> REMEDY: Calibrated two-band council gates: Gate A (publish, lower threshold) and Gate B (council, higher threshold) are distinct decisions — the verdict is a SIGNAL, a named human decision_signoff decides, minority-veto Devil's-Advocate aggregation is recorded in an immutable COUNCIL-VERDICT, and a good-faith revision may LOWER a score (never inflate it) (algos fourth look, L-3: the keystone rule that let parallel Opus-4.8 waves run trustworthily)
- GT-64: FAIL: Lets a measurement slice grow product surface, or measures against a moving baseline -> REMEDY: The golden-path invariant: a measurement harness declares ONE frozen path (frozen corpus + trace + qrels; a fixed manifest) and MEASURES against named baselines (e.g. full-read B0 and tuned-RAG B1) — everything outside the golden path is a test, a falsifier, or an evidence doc, never new product surface; value = reproducible measurement, not feature volume (q eighth look, U-3: kg-mvp Wave-5 frozen worker contract)
- GT-65: FAIL: Runs multi-lane campaigns without a stall detector, or treats lane silence as progress -> REMEDY: Corpus-wide stall detection: every multi-lane campaign carries a heartbeat-based stall detector that (a) flags any lane with no progress for 2 hours, (b) reads the heartbeat timestamps from turn-state.json, (c) escalates to HITL when 2+ lanes stall simultaneously — a lane's silence is not progress, it is a defect (filab-fourth N-7, AMENDED by operator HITL D-03: promoted from TASK-SCALE-STALL to a GT rule after the LSP runner's every-turn stall demonstrated the need at CURRENT scale, not just tens-of-thousands scale)
